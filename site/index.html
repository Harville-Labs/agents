Harville Labs engineering standards

hl plugin

One set of engineering rules, workflow skills, and review subagents that behaves the same in Claude Code, OpenCode, and Codex. It is built on Lauren Tan's (poteto) pstack. This page shows how it works, which playbook fits which task, and the principles behind each decision.

01Three layers, each loaded when needed

AGENTS.md holds the rules every session follows: read before you write, fix what you trip over, prove it works, report honestly, and keep moving until something is irreversible. It is short on purpose, because it loads into every session.

Skills hold the detail. The *-best-practices skills load when a task touches a language or topic. Workflow skills such as deslop or interrogate run when a step calls for them.

go ties it together. Hand it a task and it picks a playbook, copies the steps into the todo list, and calls the other skills at the right moment.

02What happens when you run go

  1. 1

    Restate

    Says your goal and the smallest change that meets it, before touching code.

  2. 2

    Route

    Matches the task to a playbook and copies its steps into todos.

  3. 3

    Understand

    Runs how over the subsystem, and architect when code crosses a function boundary.

  4. 4

    Delegate

    Hands code to worker subagents on a model size, not a model name.

  5. 5

    Prove

    Runs the real thing with control-cli or control-ui. A green unit test alone is not proof.

  6. 6

    Clean

    deslop before commit, no-comments before review.

  7. 7

    Open a PR

    Small ordered commits, a Why section, and docs in the same change.

  8. 8

    Babysit, ship

    Drives review and CI to green, then lands only what was verified.

03Which playbook fits?

Pick what you are trying to do. You never name the playbook yourself; go picks it from how you describe the task. Knowing the map helps you phrase the request.

04The principles

Each principle is its own small skill. go reads the ones that apply and names them in its reply, along with the choice each one changed. You can steer with them too: "apply subtract before you add". Test yourself on when each one fires.

05Sizes, not model names

No skill names a model. A skill asks for a size, and you map each size to a model you have by running . It writes ~/.config/hl/models.md with a section per harness. A missing line, or inherit, runs on the session's own model.

06When it stops to ask

Goes ahead

  • Commits, branches, pushes its own branches
  • Opens PRs and answers review threads
  • Reversible choices it can test instead of ask about
  • Fixes what it trips over, each in its own commit

Always pauses

  • Force-push to a shared branch
  • Deploys
  • Deleting data
  • Messages to customers

Say "going to bed" or "run until done" and it keeps working, with a decision log from show-me-your-work to review later. A repository's own AGENTS.md can add stop points.
