the mental model in four parts.

the 30-second explanation

hl is a plugin of engineering habits for coding agents. one entry point, go, reads your task, picks a playbook (bug fix, feature, refactor, and so on), and pulls in the skills that playbook needs. the skills are short procedures. the principles are the reasons behind them. the agents are the helpers it delegates to. it runs the same in claude code, opencode, and codex.

model sizes

skills never name a model. they name a size. ~/.config/hl/models.md maps each size to a real model per harness. a missing line means inherit, the session's own model.

  • nano explorers, investigators, trivial edits
  • small swarm workers, routine code
  • medium code delegates
  • large hardest changes, judgment, prose
  • panel list of runners for arena, architect, interrogate; first non-session vendor judges

budget

one reasoning level for the harness: unlimited, large, medium, or small. skills step it up for the hardest work and down for routine work.

go and its playbooks

the front door. everything else is reachable from here.

go

routes a nontrivial task to a playbook, applies the principles, delegates on purpose, and verifies before reporting.

non-negotiables (triggers)
  • first message: restate the goal, the problem, and the smallest change you expect. don't wait for a yes.
  • nontrivial change or "are we sure?": run how.
  • about to ask a "which approach" question: if running something would answer it, run it instead of asking.
  • any code: name the data shape first (model-the-domain).
  • code crossing a function boundary: architect.
  • parallel fan-out: swarm. design bakeoff: arena. contested design: interrogate.
  • any prose, including the reply: unslop. docs, PRs, commits: technical-writing.
  • before commit: deslop. before review: no-comments.
  • shipping a UI, CLI, or TUI: control-ui or control-cli. bugs get reproduced on the real surface first.
  • any number you measured: benchmark-checklist before you report it.
  • PR status requests: babysit playbook. "land it": shipping playbook.
  • review bots: skeptical. judge each comment on its merits.
  • broken skill: fix it in its own PR, don't silently work around it.
  • long or unattended work: a decision trail via show-me-your-work.
  • cite only principles whose SKILL.md you actually read this session.
other sections

autonomy (keep moving, stop only at the irreversible), subagents (pick a size and effort per job), models (read models.md once per session), writing the reply, comments, and the playbook index.

say itgo is the dispatcher: it reads the task, picks the recipe, and holds the agent to a short list of rules that always apply.

feature

you own the design. delegate implementation.

  1. how over the subsystem
  2. architect for parallel designs
  3. throughput checkpoint
  4. delegate, review, verify on the real surface
  5. opening a PR

bug fix

every shipped line traces to runtime evidence.

  1. reproduce it yourself on the real surface
  2. failing test first when there is a cheap local path; otherwise an executable repro
  3. find the root cause, not a symptom
  4. revert anything a refuted hypothesis motivated
  5. smallest fix, verify, PR

refactoring

structure changes, behavior doesn't.

  1. pin the contract with a characterization test or snapshot
  2. change structure in small verified steps
  3. split out any bug or feature you find

perf issue

every fix tied to a measurement.

  1. baseline trace, vetted by benchmark-checklist
  2. how to ground hypotheses
  3. one change, one measurement

hillclimb

sustained improvement of one metric.

one change, one measurement, keep or revert. never stack untested changes. ground the workload before picking the metric.

investigation

read-only. the output is a cited answer.

route through how, plus why for motivation questions.

prototype

a throwaway instrument for one decision.

speed over polish. no decision to make means no prototype. the real build goes through feature.

multi-phase plan

the plan is the deliverable. don't implement.

skip it for one or two obvious files. settle open questions by prototype. write a checklist an owner runs box by box.

opening a PR

the end of every other playbook.

read AGENTS.md and the issue, work in a worktree on <type>/<issue>-<slug>, size and stack PRs, honest body.

babysit

own the merge frontier.

declare a mode (drive or background), resolve the forge (gh or glab), clear one PR at a time, stop where the human's call begins.

shipping

green is not safe.

an independent verifier per PR. land only the contiguous verified run from the bottom of the stack.

autopilot-full / -stack

one owner per PR from build to merge.

a swarm that never wrote the code proves it. the stack variant stops at verified and hands off without merging.

autonomous run

define done, then drive to it.

a checkable exit predicate first. wake on events with a watcher plus a long heartbeat.

orchestrate

run the program, never the code.

multi-day work: decide which agent does each piece, keep state in a committed notes.md, check every output.

eval

design, blind, run, synthesize.

the candidate never sees words like eval, judge, rubric, or benchmark anywhere.

runtime / trace forensics

diagnose from evidence, not source.

runtime: capture a live profile, heap, or trace. trace: the artifact already exists, so read it, don't rerun it. reduce to the smoking gun in a subagent.

visual parity

the baseline is the spec.

image diff, not eyes. no harness changes, no baseline tampering.

session pickup / pause safely

resume from the trail; stop with a checkpoint.

pickup reads the prior transcript and git state. pause stops at a safe boundary with no irreversible action.

authoring a skill / worktree cleanup

housekeeping.

skills: frontmatter is name and description only, validate links. cleanup: audit with a script, verify no active chat uses a worktree before deleting.

think and design

understanding before changing, and comparing options before committing.

how

explains how code works.

steps
  1. assess complexity
  2. simple: one explainer
  3. complex: parallel explorers, then a synthesizer, then present
use for

walkthroughs, "where should this live", grounding before a change.

say ithow sends readers through the code and comes back with a map.

why

explains why code is the way it is.

steps
  1. pin the code anchor
  2. one investigator per evidence source: git (always), issues, docs, chat, observability, errors, analytics
  3. synthesize with the epistemics rules and record null results
rule

skip a source only when no tool reaches it (flag the gap) or it is provably irrelevant.

say itwhy is archaeology: it digs through history and context to recover the reason behind a line.

architect

designs before code crosses a function boundary.

  1. ground (how)
  2. sketch types, signatures, modules, using arena
  3. agree (opt-in)
  4. implement against the sketch

if the shape is wrong: rerun how, redesign from first principles, subtract, sketch again.

say itarchitect sketches the types and seams first, so the code fills in a shape someone already checked.

arena

a bakeoff between competing implementations.

  1. frame the artifact and a 3–6 item rubric only the picker sees
  2. one runner per panel entry, each in its own worktree
  3. cross-judge, pick a base
  4. graft the best parts of the losers
  5. verify
say itarena has several models build the same thing, judges them, and merges the winner with the best ideas from the rest.

swarm

parallel fan-out for coverage or races.

  1. frame a done predicate and a shape: slices, a race, or mixed
  2. workers on small, each with its own output and exact SHAs
  3. fan out, aggregate, report
say itswarm splits a big job across many cheap workers and stitches the results.

interrogate

adversaries try to break a change.

multiple models attack it. only findings proven by an actual run survive.

output

intent, findings (command, output, how it breaks, who found it), dropped counts.

say itinterrogate is a red team where a finding only counts if it reproduces.

figure-it-out

builds a playbook when none fits.

  1. frame
  2. design the workflow, rigor scaled to the task
  3. run a hypothesis loop
  4. keep an audit trail
  5. verify and hand back
say itthe fallback for odd tasks: invent a method, then run it scientifically.

sharpen

makes a task deeper, not bigger.

asks four questions, then rewrites the prompt:

  1. what would a top pro do that I'm not asking for?
  2. what is the rawest material?
  3. which methods and tools?
  4. what external check proves it right?
say itsharpen upgrades a vague ask into what an expert would actually do.

statechart

draws a system's states.

writes a TLA+ spec plus a view module and renders it as mermaid.

say ita checked state machine you can also look at.

blast-radius

what could this change break?

ranks callers on a certainty ladder, names "the one fact" the safety depends on, and looks where grep stops (reflection, config, other repos).

say itimpact analysis that admits what it can't see.

code quality and review

tdd

test-driven development.

use a failing test when there is a cheap local path; otherwise use an executable regression check. never weaken an assertion to pass.

say itred, green, and no cheating the test.

deslop

cleans the diff so it reads hand-written.

targets

defensive noise, swallowed errors, escape-hatch types, speculative abstraction, duplication, narrating comments, leftovers, off-style code, over-logging, test slop.

rule

touches only the diff.

say itdeslop removes the tells of AI-written code before commit.

no-comments

audits comments before review.

spawns comment-auditor, vets its report, removes MUST KILL comments. a comment stating a constraint becomes a type, check, test, or lint.

say itcomments that narrate die; comments that guard become code.

self-review

reviews your own diff before you say done.

runs the diff through checklists, reruns the check command, lists what's unverified.

say itthe agent reviews itself honestly before a human has to.

correct

fixes classes of mistakes, not instances.

finds mistakes that happened at least twice and fixes each at the highest level: architecture, then types or lint, then tests, then docs. keeps a rule table.

say itif it happened twice, make it impossible.

benchmark-checklist

vets a number before you trust it.

seven questions, starting with "why not double?". at least five alternating runs.

say itno speedup claim survives without controls.

writing

unslop

prose rules for anything a person reads.

a numbered list of rules against filler, hype, hedging, stock phrases, and rhythm tics. go applies it to every reply.

say itdeslop for words.

technical-writing

the house style for docs, PRs, and commits.

layers
  • three top rules: cut dead words, use short words, break a rule if it makes the sentence worse
  • diátaxis picks the mode: tutorial, how-to, reference, explanation. never mix
  • google style: "you", present tense, active voice, condition first
  • simplified technical english: one instruction per sentence, about 20 words
  • global english: no idioms, slashes, or latin
say itplain, specific, translatable writing with one job per page.

update-docs

finds every doc a change touches.

searches for every mention, then a table maps change type to doc: config key, env var, CLI flag, protocol, route, invariant, changelog. checks links, commands, and examples.

say itdocs ship in the same PR, found by search, not memory.

write-adr

records a decision.

when an invariant changes or you chose between real alternatives. NNNN-kebab.md with context, decision, alternatives, consequences. never edit an accepted one; supersede it.

say itthe answer to "why did we do it this way?" written before anyone asks.

write-agents-md

writes a repo's AGENTS.md.

research the repo, then: what it is, commands (run them), layout, invariants, common changes, conventions, things not to do. under about 250 lines. wires CLAUDE.md with @AGENTS.md.

say itan onboarding doc for agents, checked against reality.

context and memory

recall

rebuilds context from recent chats.

capsule, threads with status tags, problems, next move.

catchup

read-only "what did I miss".

what happened in under 100 words, about 30 words per action item, pictures where they help.

catchup-video

catchup as a short video.

a subtitled mp4 slideshow of at most 10 slides.

reflect

learns from a session.

judgment, tooling, and divergent reviewers, then a synthesizer. waits for approval. never edits the plugin cache.

show-me-your-work

a decision log for unattended work.

appends TSV rows with a script, audits them against the transcript, ends with a reviewed-by line.

say itreceipts for every call the agent made while you were away.

teach

how plus why, for a learner.

plain definition first, conversational.

in-your-own-words

restates your goal.

catches misunderstanding before work starts.

help

which skill do I want?

a picker table plus the close calls between similar skills.

automate-me

builds your personal mode.

reads your transcripts and writes a <handle>-mode skill of how you work.

setup-models

maps sizes to real models.

  1. list models the harness offers (never write one you haven't seen)
  2. load the current file
  3. ask for a budget
  4. propose a model per size
  5. write ~/.config/hl/models.md
  6. confirm; applies to new sessions
  7. offer verification skills

verification and driving apps

control-cli

drives a CLI or TUI like a user.

isolated HOME, exit codes checked, tmux keystrokes and screen captures for TUIs.

control-ui

drives a web or electron UI like a user.

harness browser, then playwright, then electron. role locators, no sleeps. saves screenshots, console errors, failed requests.

create- / maintain-verification-skill

a project skill for driving the real app.

generates .agents/skills/verify-<app> and keeps it in sync as the app changes.

create- / maintain-formal-verification-skill

proofs instead of samples.

TLA+ or similar model checks that must be able to fail, kept in sync with the code.

say ittests check examples; these check every case in scope.

building and dependencies

add-dependency

before you install a package.

check if one exists already, evaluate maintenance, size, license, fit, and security, and justify it in the PR.

add-service

a new deployable service.

PORT, /healthz, SIGTERM handling, a multi-stage Dockerfile that runs checks, image workflow, k8s manifests with a deny-all egress NetworkPolicy, and an infra handoff list.

slack automation

triage-issue-reports

triages a bug report thread.

safety

frozen channel and thread; never post at root, cross-post, or DM; only the coordinator posts.

steps
  1. freeze coordinates, read everything
  2. trace the cause with how and why
  3. classify: bug, performance, feature, question, reroute
  4. route; owner pings off by default
  5. dedupe against the tracker
  6. create an issue only when all conditions hold
  7. post one verdict with a marker like [hl:bug], verify it landed
  8. watch one follow-up window

reproduce-and-fix-issues

from report to draft PR.

reproduces twice, fixes, opens a draft PR. never merges.

best practices

rule tables. go, python, rust, svelte, and typescript load only when called.

code

files under 500 lines, split by responsibility, one home per rule, types from one source, alike isn't duplicate, libraries over hand-rolled.

testing

a table of checks for each change, including a regression check when a new test is impractical; hermetic tests, outcomes not calls, no sleeps.

security

no committed secrets (rotate, don't just delete), schemas at the boundary, allow-lists, confined paths, bound what strangers can spend, no shells, private by default, isolated networks, hardened containers.

git

issue first, <type>/<issue>-<slug>, conventional commits, one change per PR, honest "how it was tested", squash, changelog in the same PR, semver by tag.

deploy

app owns image and manifests, infra owns shared resources. main deploys by sha tag, never hand-edit pins, small non-root images, plain kustomize, NetworkPolicy.

typescript

discriminated unions, branded types, unknown over any, schemas before guards, no as, never exhaustiveness, satisfies, strict ESM, vite, biome, bun.

svelte

runes only, snippets not slots, $derived computes and $effect syncs, markup used twice is a component, tailwind only, library widgets, accessibility checklist.

python

uv for everything, ruff and ty, one check command, typed signatures, pydantic at the boundary, pathlib, hermetic pytest.

go (language)

static binary, cmd wires and internal works, stdlib first, wrapped sentinel errors, deadlines everywhere, hardened http.Server, table tests.

rust

pinned toolchain, clippy -D warnings, thin binaries, types model states, no panics on input, no unsafe without an ADR, deterministic output.

principles

the 25 reasons. go cites them; they never fire on their own.

core

  • laziness-protocol consolidate decisions, minimize the diff, bias to deletion
  • foundational-thinking data structures first, scaffold first
  • redesign-from-first-principles rebuild as if the requirement existed on day one
  • attack-the-premise two failed fixes on one premise: test the premise
  • subtract-before-you-add
  • minimize-reader-load the 30-second test
  • outcome-oriented-execution end state over smooth steps
  • experience-first the user includes the next maintainer
  • exhaust-the-design-space 2–3 prototypes for novel calls
  • build-the-lever script it; do the first unit by hand and diff

architecture

  • model-the-domain state machines, typed models, registries, reducers
  • boundary-discipline parse at the edge, trust inside
  • type-system-discipline brand primitives, derive from schemas
  • make-operations-idempotent safe to rerun
  • migrate-callers-then-delete-legacy-apis
  • separate-before-serializing-shared-state

verification

  • prove-it-works the real artifact, scripted checks
  • fix-root-causes reproduce, ask why repeatedly, suspect persisted state
  • sequence-verifiable-units small units, each verified before the next
  • test-behavior-not-implementation
  • explain-the-number decide what it means before you look
  • encode-lessons-in-structure a repeated instruction becomes a lint or check

delegation

  • guard-the-context-window route bulk work to subagents
  • never-block-on-the-human proceed, then present; confirm only the irreversible

agents

worker

go's delegate.

reads go and the cited principles, does the work, reports what changed, what ran, and what wasn't verified.

reviewer

read-only code review.

diffs main...HEAD against AGENTS.md and the org rules. reports only confirmed findings with file, line, and triggering input.

verifier

runs the full check, never fixes.

reports a table and ends green, red, or partial.

comment-auditor

the comment sicko.

keeps legal headers, external constraints, justified suppressions, public API docs, issue links. everything else is MUST KILL. reports only.

no skills match that filter.
